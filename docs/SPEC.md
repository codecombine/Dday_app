### 핵심 원칙
1. **데이터는 하나, 공유 범위만 다르게.** 일정이나 사진은 한 번만 저장하고 "어느 공간에서 보일지"만 붙인다. 고치면 모든 공간에 함께 반영된다.
2. **원본은 하나만.** 같은 사진이 여러 번 올라오면 원본 하나만 남긴다. 단, 지우는 건 항상 사람이 확인한 뒤에 한다.
3. **쉬운 참여.** 카카오톡 초대 링크와 버튼 한 번으로 가입·참여가 끝나야 한다.
4. **옮길 수 있는 저장소.** 사진 저장소(R2)는 나중에 NAS로 옮길 수 있게 분리해 둔다.

## 1. 용어

## 2. 가입과 로그인

### 2.1 로그인 수단
- **카카오** (기본으로 가장 크게 표시), **Google**, **이메일·비밀번호** (가입 시 인증 메일, 비밀번호 재설정 지원)
- 로그인은 필수다. 공유가 핵심이라 계정 없이 쓰는 모드는 없다.
- 카카오 로그인은 서버(Worker)가 카카오 사용자 정보를 확인한 뒤 Firebase 맞춤 토큰을 발급하는 방식이다. Firebase 사용자 ID는 `kakao:<카카오 회원번호>`.

### 2.2 첫 로그인 처리
- 사용자 문서(`users/{uid}`)와 **개인 공간**("나만")을 자동으로 만든다.
- 초대 링크로 들어왔다면 로그인 직후 그 공간에 자동으로 참여한다.

### 2.3 초대
- 관리자가 공간에서 **초대 링크**를 만든다. 카카오톡 공유 또는 링크 복사로 보낸다.
- 링크 형식: `https://<웹 주소>/invite/<토큰>`. 앱이 설치돼 있으면 앱으로 열리고, 없으면 웹에서 가입 후 참여한다.
- 링크는 **7일 동안 여러 번** 쓸 수 있다. 관리자가 언제든 무효화할 수 있다.
- 초대 화면에는 공간 이름, 초대한 사람, 구성원 수, 공유된 일정·사진 수를 보여준다.
- 프로필 구성원(예: 외할머니)을 대상으로 초대하면, 그 사람이 가입할 때 기존 프로필과 자동으로 연결된다. 그동안 그 프로필로 표시된 일정 참석 기록이 그대로 이어진다.

## 3. 공간과 권한

### 3.1 공간
- 개인 공간: 사람마다 1개. 이름은 "나만", 구성원은 본인뿐이다. 나갈 수 없다.
- 공용 공간: 누구나 만들 수 있다. 만든 사람이 관리자가 된다. 이름과 색상(10개 팔레트)을 정한다.
- 한 사람이 여러 공용 공간에 속할 수 있다 (예: 우리집 + 외가 + 시댁).

### 3.2 공유 범위 규칙
- 모든 항목·사진·앨범은 공유 범위를 **1개 이상** 가진다.
- "나만 보기" = 개인 공간만 선택한 상태. "나만 보기"를 고르면 다른 공간 선택이 풀리고, 다른 공간을 고르면 "나만 보기"가 풀린다.
- 내가 속한 공간에만 공유할 수 있다.
- **볼 수 있는 사람** = 공유 범위에 있는 공간들의 계정 구성원 전체(중복 제거). 화면에 미리 보여준다.

### 3.3 권한 표

| 동작 | 누가 |
|---|---|
| 항목·사진 보기 | 공유 범위 공간의 구성원 |
| 항목 수정 | 만든 사람. "다른 가족도 수정 가능"이 켜져 있으면 볼 수 있는 구성원 모두 |
| 항목 삭제 | 만든 사람 |
| 항목을 특정 공간에서 빼기 | 만든 사람, 또는 그 공간의 관리자 (그 공간에서만 빠짐) |
| 사진 삭제(휴지통) | 올린 사람. 공간 규칙이 "올린 사람과 관리자"면 그 공간 관리자도 그 공간에서 뺄 수 있음 |
| 공간 이름·색상·규칙 변경 | 관리자 |
| 구성원 초대·내보내기, 관리자 지정, 프로필 구성원 추가 | 관리자 |
| 중복 사진 검토·정리 | 관리자 |

### 3.4 공간 규칙 (관리자가 정함)
| 규칙 | 선택지 | 기본값 |
|---|---|---|
| 사진 지우기 | 올린 사람만 / 올린 사람과 관리자 | 올린 사람만 |
| 가족이 공간을 나가면 그 사람이 올린 사진 | 공간에 남기기 / 함께 지우기 / 나가는 사람이 고르기 | 나가는 사람이 고르기 |
| 일정 수정 기본값 | 만든 사람만 / 구성원 모두 | 만든 사람만 |

"공간에 남기기"를 고르면 그 사진의 소유권은 공간 관리자에게 넘어간다.

### 3.5 공간 나가기·내보내기
- 나가면 그 공간 공유 범위에서 내 항목이 빠진다. 다른 공간에도 공유돼 있던 항목은 그대로 남는다.
- 사진은 위 규칙을 따른다.
- 마지막 관리자는 다른 관리자를 지정하기 전까지 나갈 수 없다. 혼자 남은 공간에서 나가면 공간이 삭제된다.

## 5. 기념일·D-Day

### 5.1 유형
| 유형 | 예 | 표시 |
|---|---|---|
| 카운트다운 | 시험, 여행 | D-n → D-Day → D+n |
| 지난 날부터 세기 | 아이 태어난 날, 사귄 날 | n일째, 경과 기간(n년 n개월 n일), 다가오는 기념일 |
| 매년 반복 | 생일, 결혼기념일, 기일 | 다음 날짜까지 D-n |
| 매월 반복 | 월급날 | 다음 날짜까지 D-n |

### 5.2 계산 규칙
- 기준 시간대는 기기 시간대(한국은 Asia/Seoul). 날짜는 하루 단위로만 계산하고 시각은 무시한다.
- **D-n**: 목표일 − 오늘(일). 0이면 "D-Day", 지났으면 "D+n".
- **n일째**: "1일부터 세기"가 켜져 있으면 (오늘 − 시작일) + 1, 꺼져 있으면 (오늘 − 시작일). 기념일 유형은 기본으로 켠다.
- **다가오는 기념일**:
  - 100일 단위(100, 200, …), 1000일 단위(1000, 2000, …), 매 주년(1주년, 2주년, …)
  - "1일부터 세기"가 켜져 있으면 100일째 = 시작일 + 99일
  - 주년은 같은 월·일. 2월 29일 시작이면 평년에는 2월 28일
  - 상세 화면에는 앞으로 오는 것 3개를, 카드에는 가장 가까운 것을 보여준다
- **매년 반복**: 올해 날짜가 지났으면 내년. 2월 29일은 평년에 2월 28일.
- **매월 반복**: 그 달에 해당 일이 없으면 말일 (예: 31일 → 30일·28일).
- **음력**: 매년 반복일 때만 선택한다. 매년 해당 음력 날짜를 양력으로 바꿔 계산한다.
  - 윤달 생일은 그해에 같은 윤달이 있으면 윤달, 없으면 평달로 계산한다.
  - 해당 음력 월에 그날이 없으면(30일이 없는 작은달) 그 달 말일로 계산한다.
  - 지원 범위는 1900~2050년이다(변환 라이브러리 한계).
- **경과 기간**: 시작일부터 오늘까지 n년 n개월 n일. 일이 음수면 전달 말일 수로 빌려온다.

### 5.3 목록과 정렬
- 가까운 날짜 순. 내가 고정한 항목은 맨 위에 둔다.
- 날짜가 지난 카운트다운은 아래쪽 **"지난 항목 n개"**로 접는다. 지난 날부터 세기·반복 항목은 늘 위에 남는다.
- 위쪽 공간 칩(전체 / 나만 / 공간들)으로 걸러 본다.

## 8. 앨범·사진

### 8.1 보기
- 위쪽 공간 칩, "중복 사진 n장 정리 가능" 배너(관리자에게만), 앨범 목록, 날짜별 사진 묶음
- 사진을 누르면 전체 화면 보기. 넘기기, 확대, 정보(찍은 날, 기기, 올린 사람, 공유 범위), 원본 다운로드
- 가족 저장공간 사용량 표시

### 8.2 올리기
- 폰 갤러리에서 여러 장을 고른다. 웹은 파일 선택이나 끌어놓기로 올린다.
- 앨범 선택(선택), 공유 범위 선택(필수), 화질 선택:
  - **원본 그대로** (기본): 파일을 그대로 보관한다
  - **용량 절약**: 긴 변 2048px, JPEG 품질 85
- 올리기 전에 폰에서 사진마다 다음을 계산한다:
  - 파일 지문(SHA-256)
  - 생김새 지문(64비트 pHash)
  - 가로·세로, 용량, 촬영 정보 유무, 촬영 일시, 기기 이름
  - 출처 추정: 카메라 / 카카오톡 / 화면 캡처 / 알 수 없음
- **볼 수 있는 사진 중에 같은 파일이 이미 있으면 올리지 않고**, 기존 사진의 공유 범위·앨범에 추가할지 묻는다.
- 미리보기(긴 변 1600px)와 썸네일(긴 변 400px)을 폰에서 만들어 원본과 함께 올린다.
- "가족에게 알림 보내기"를 켜면, 볼 수 있는 가족에게 묶음 알림을 보낸다 ("아빠가 사진 12장을 올렸어요").

### 8.3 자동 올리기 (사용자 선택, 기본 꺼짐)
- 올릴 폴더(기본: 카메라), 기본 공유 범위(기본: 나만 보기), 조건(Wi-Fi·충전 중)을 정한다.
- 앱을 열 때와 백그라운드 작업에서 새 사진을 찾아 올린다.
- 영상은 1단계에서 자동으로 올리지 않는다.

### 8.4 전체 가져오기
- 설정 > 사진 > "폰 사진 전체 가져오기". 기간과 폴더를 고르고, 기본 공유 범위를 정한다.
- 충전 중·Wi-Fi일 때 천천히 올린다. 진행률을 보여주고, 중단했다가 이어서 할 수 있다.
- 같은 파일은 건너뛴다. 사본 후보는 올린 뒤 중복 정리에서 검토한다.

### 8.5 휴지통
- 지운 사진은 30일간 휴지통에 있다가 완전히 삭제된다. 휴지통에서 되살릴 수 있다.

## 9. 중복 사진 정리

### 9.1 분류
| 분류 | 판정 | 처리 |
|---|---|---|
| 같은 파일 | SHA-256이 같음 | 원본 1장을 남기고 나머지를 "지우기"로 미리 선택 |
| 화질 낮은 사본 | pHash 거리 ≤ 6 **그리고** 해상도(픽셀 수)가 1.2배 이상 차이 나거나, 한쪽에만 촬영 정보가 있거나, 한쪽 출처가 카카오톡 | 원본 1장을 남기고 사본을 "지우기"로 미리 선택 |
| 비슷한 사진 | pHash 거리 ≤ 10이고 위 조건에 안 맞음 (연사 등) | 아무것도 미리 선택하지 않음. 제안만 |

pHash 거리는 64비트 중 다른 비트 수다. 기준값은 실제 사진으로 조정할 수 있게 서버 설정으로 둔다.

### 9.2 원본 고르는 순서
1. 픽셀 수가 큰 것
2. 촬영 정보(EXIF)가 있는 것
3. 용량이 큰 것
4. 촬영 일시가 이른 것
5. 먼저 올라온 것

### 9.3 검토와 정리
- 공간 관리자가 그 공간에서 보이는 사진을 대상으로 검토한다.
- 사진이 올라올 때마다 서버가 후보를 찾아 갱신한다. "다시 검사"로 전체를 다시 볼 수도 있다.
- 묶음마다 사진별로 남기기/지우기를 바꿀 수 있다. "선택한 n장 휴지통으로"로 한 번에 정리한다.
- **정리할 때 합치기**: 지우는 사본의 공유 범위·앨범을 원본에 합친다. 사본에만 있던 촬영 일시는 원본 것을 쓴다.
  - 예외: 합치면 원본이 **원본 주인이 정하지 않은 공간에 새로 보이게** 되는 경우, 원본 주인에게 확인 요청을 보낸다. 주인이 승인하기 전까지 그 사본은 지우지 않는다.
- 자동 삭제는 절대 하지 않는다. 지운 사진은 휴지통에서 30일간 되살릴 수 있다.

### 9.4 1단계에서 못 잡는 것
잘라낸 사진, 필터·스티커를 넣은 사진, 화면 캡처본, 영상(같은 파일만 잡음). 2단계에서 AI 이미지 비교로 확장한다.

## 10. 구글 캘린더 실시간 동기화
- 설정 > 연동 > Google 캘린더 "연결". 구글 동의 화면에서 권한을 허용한다.
- 권한은 **앱이 만든 캘린더만 접근**하는 가장 좁은 범위(`calendar.app.created`)만 요청한다.
- 연결하면 내 구글 캘린더에 **"한지붕"** 캘린더를 만든다. 내가 볼 수 있는 항목을 일정으로 넣는다. 반영할 공간은 고를 수 있다(기본: 전체).
- 반영 규칙:
  - 종일 일정은 종일로, 시각 일정은 시각대로 넣는다. 반복은 반복 일정(RRULE)으로 넣는다.
  - 음력 매년 반복은 앞으로 10년치를 일정 하나씩 따로 만든다.
  - 지난 날부터 세기 항목은 앞으로 1년 안에 오는 기념일(100일 단위, 주년)을 일정으로 넣는다.
- **앱 → 구글**: 항목이 바뀌면 서버가 즉시 반영한다.
- **구글 → 앱**: "한지붕" 캘린더에서 제목·날짜를 고치면 구글이 서버에 변경 알림을 보내고, 서버가 앱 항목을 고친다.
  - 그 사람에게 수정 권한이 없으면 앱 내용으로 되돌린다.
  - 구글에서 일정을 지우면 그 사람 캘린더에서만 빠지고 항목 자체는 지우지 않는다.
- 서버는 구글 토큰을 암호화해서 D1에 보관한다. 변경 알림 채널은 만료되기 전에 정기 작업으로 갱신하고, 놓친 변경을 보정한다.
- 연결 해제 시: 구글 권한을 철회하고 서버 토큰을 삭제하며, "한지붕" 캘린더를 지울지 묻는다.
- 운영: 가족 전용이라 구글 앱 심사 없이 '프로덕션·미확인' 상태로 운영한다. 사용자 100명 제한이 있고, 동의 화면에 "확인되지 않은 앱" 경고가 뜬다.

## 17. 시스템 구조

```
[안드로이드 앱 / 웹] ──로그인────────────▶ Firebase Auth (이메일·구글, 카카오는 맞춤 토큰)
        │          ──항목·공간·사진 정보──▶ Firestore (실시간 구독, 보안 규칙으로 권한 검사)
        │          ──초대·사진 파일·중복정리·캘린더 연동──▶ Cloudflare Worker (api.<도메인>)
        │                                         ├─ D1: 구글 토큰(암호화), 캘린더 매핑, 사진 지문, 초대
        │                                         ├─ R2: 사진 원본·미리보기·썸네일 (저장소 계층 뒤)
        │                                         ├─ Google Calendar API ◀─ 변경 알림(webhook)
        │                                         ├─ FCM (푸시)
        │                                         └─ 정기 작업: 채널 갱신, 동기화 보정, 휴지통 비우기
[Cloudflare Pages] ── 웹 앱 정적 파일
```

### 17.1 권한 전달 방식
- 사용자가 속한 공간 목록은 **Firebase 맞춤 클레임**(`spaces`)에 넣는다. Firestore 보안 규칙과 Worker 모두 로그인 토큰만 보고 권한을 판단한다(추가 조회 없음).
- 공간 참여·탈퇴는 Worker만 처리하고, 처리 후 클레임을 갱신한다. 앱은 토큰을 새로 받는다.

### 17.2 사진 저장소 계층 (R2 → NAS 이전 대비)
1. 앱은 사진 주소를 저장하지 않는다. Worker에 "사진 n장의 주소"를 요청하면 Worker가 권한을 확인하고 **1시간짜리 서명 주소**를 준다.
2. Firestore와 D1에는 사진 ID와 지문만 저장한다. 실제 위치는 Worker의 저장소 계층이 알고 있다.
3. 원본·미리보기·썸네일을 따로 저장한다: `photos/<사진ID>/original`, `photos/<사진ID>/preview.jpg`, `photos/<사진ID>/thumb.jpg`
4. 저장소 계층은 `put / get / head / delete` 네 가지 기능만 가진다. R2 구현을 먼저 만들고, NAS 구현(S3 호환 + Cloudflare Tunnel)은 나중에 추가한다.
5. 이전 순서: NAS 자동 백업(A) → 원본은 NAS, 미리보기는 R2(B). 전부 NAS(C)는 권하지 않는다.

## 20. 보안·개인정보
- Firestore 보안 규칙으로 모든 읽기·쓰기를 공간 클레임 기준으로 검사한다.
- 사진 파일은 서명 주소로만 받을 수 있다(1시간 만료). R2 버킷은 공개하지 않는다.
- 구글 토큰은 AES-GCM으로 암호화하고, 키는 Worker 비밀값으로 둔다.
- 서비스 계정 키, 카카오·구글 클라이언트 비밀값은 Worker 비밀값과 환경 비밀값으로만 관리하고 레포에 넣지 않는다.
- 위치 정보: 사진의 GPS는 원본 파일 안에만 있다. 앱 화면에는 표시하지 않는다(1단계).
- 개인정보처리방침에 수집 항목(계정, 일정, 사진, 구글 캘린더 토큰, 기기 푸시 토큰), 보관 위치(Firebase·Cloudflare), 보관 기간, 삭제 방법을 적는다.
